== Context and Scope

In diesem Kapitel wird das System gegenüber externen Akteuren und angebundenen Nachbarsystemen abgegrenzt. Es werden die fachlichen Interaktionen (Business Context) sowie die konkreten technischen Schnittstellen, Übertragungsmedien und Protokolle (Technical Context) definiert.

=== Business Context

Der fachliche Kontext beschreibt die Systemgrenzen aus Sicht der Anwender (Studierende, Dozierende, Robotik-Entwickler). Der Benutzer interagiert ausschliesslich mit der bereitgestellten Python-Bibliothek. Das System übernimmt die interne Ablaufsteuerung, die Validierung der Parameter sowie die Weiterleitung der Steuer- und Umgebungsbefehle an die Simulationsumgebung, die reale Roboterhardware oder an beide Zielsysteme gleichzeitig.

image::ContextDiagramm.png[align=center, width=80%]

[cols="1,2,2", options="header"]
|===
| Akteur / Nachbarsystem | Rolle und fachliche Aufgabe | Schnittstelle / Interaktion

| **Benutzer / Entwickler**
| Erstellt Ablaufprogramme in Python, definiert Bewegungsabläufe und steuert Endeffektoren sowie Simulationsszenarien.
| Ruft die Methoden der Klassen `Robot` und `World` auf. Erhält visuelles Feedback über die Simulation oder physische Rückmeldung durch den Roboter.

| **Digital Twin System (Python API)**
| Kapselt die interne Ablauflogik, validiert Eingabewerte (Winkel, Geschwindigkeit, Farben), verwaltet den simulierten Zustand und leitet Befehle modusspezifisch weiter.
| Zentrale Steuerungsinstanz; entkoppelt den Benutzercode von hardware- und netzwerkspezifischen Details.

| **Unity Simulation**
| Visualisiert den Roboterarm, führt die physikalische Gelenkbewegung aus, simuliert Greif- und Saugvorgänge und verwaltet dynamisch erzeugte Umgebungsobjekte.
| Empfängt Steuerdaten für Roboter und Welt; stellt das Verhalten in einer 3D-Szene in Echtzeit dar.

| **MyPalletizer 260 M5 (Hardware)**
| Führt die physischen Bewegungen und Werkzeugaktionen in der realen Welt aus.
| Empfängt Gelenkwinkel und Steuerkommandos über die serielle Schnittstelle.
|===

=== Technical Context

Der technische Kontext definiert die konkreten Schnittstellen, Übertragungsmedien, Protokolle und Datenformate zwischen dem Python-Steuerungssystem und den angebundenen Systemen.

image::TechnicalContext.png[align=center, width=85%]

[cols="1,1,1,3", options="header"]
|===
| Schnittstelle | Übertragungsmedium | Protokoll / Format | Technische Beschreibung

| **Benutzerprogramm zu Python API**
| In-Process Funktionsaufruf
| Python 3 API (Objektorientiert)
| Direkter Methodenaufruf auf den Klassen `Robot` und `World` mit nativer Typisierung und Validierung.

| **Python API zu Unity: Roboterkanal**
| UDP Socket (`localhost`)
| JSON über UDP (Port `5005`)
| Überträgt Bewegungsbefehle (`move_joints`, `sync_move_joints`), LED-Farben (`led`) und Werkzeugbefehle (`set_end_effector`, `set_gripper_state`, `pump`) im UTF-8-JSON-Format.

| **Python API zu Unity: Weltkanal**
| UDP Socket (`localhost`)
| JSON über UDP (Port `5006`)
| Überträgt Befehle zur Szenenverwaltung (`spawn`, `delete`, `clear`) inklusive geometrischer Daten (Position, Rotation, Skalierung, Farbe) im UTF-8-JSON-Format.

| **Python API zu MyPalletizer Hardware**
| USB / Serial (Virtueller COM-Port / `/dev/ttyUSB*`)
| Serielles Binärprotokoll (`pymycobot`), `115200` Baud
| Sendet Gelenkwinkel (`send_angles`, `sync_send_angles`), Pin-Zustände für Relais (`set_basic_output`) und liest Hardware-Telemetrie (`get_angles`).
|===
